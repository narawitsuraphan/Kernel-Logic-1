ALGORITHM & DATA STRUCTURE MASTERY
==================================================

Protocol for every algorithmic task:

1. State O(n) time and O(n) space complexity at the top of the function.
2. Justify data structure choice (Map vs Object, Set vs Array, Heap vs sorted Array).
3. Note rejected alternatives and why (e.g., "Brute force O(n²) rejected — hash map gives O(n)").
4. Handle all boundary conditions explicitly: empty input, single element, max constraints.
5. Write readable code first — optimize with inline explanatory comments.
6. Include 2-3 traced examples (input → expected output) as comments.

Data Structure Decision Guide:
- Key-value lookup → Map (not plain Object for non-string/symbol keys)
- Uniqueness → Set
- Priority ordering → Min/Max Heap
- Prefix/autocomplete search → Trie
- Graph traversal → Adjacency list + BFS (shortest path) or DFS (cycle detection, topological sort)
- Range queries → Segment Tree or Binary Indexed Tree (Fenwick)
- Interval merging → Sort by start, linear sweep
- LRU Cache → Map (insertion-order iteration) + size limit eviction

COMPLEX SYSTEM SPECIALIZATIONS
==================================================

REAL-TIME:
- WebSocket: Exponential backoff reconnection (1s, 2s, 4s, 8s → max 30s cap) + connection status indicator.
- SSE: EventSource with retry + last-event-id header for resumption.
- Optimistic UI: Apply update immediately to local state → confirm on server response → roll back with toast on error.
- Presence/typing: Debounce broadcasts to 50ms to avoid flooding.

ASYNC ORCHESTRATION:
- Parallel independent requests: Promise.all with per-request error isolation.
- Sequential dependent: async/await chain with descriptive variable names at each stage.
- Cancellable: AbortController — cancel on component unmount or when superseded by newer request.
- Deduplication: Cache in-flight promises by request key.
- Retry: Exponential backoff with jitter. Classify errors — retry transient (503, network), fail fast on client errors (400, 401).

STATE MACHINES:
Model every complex flow as explicit states. Never use boolean flag soup.
```typescript
type Status = 'idle' | 'loading' | 'success' | 'error' | 'retrying'
type State =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: ResponseData }
  | { status: 'error'; error: AppError; retryCount: number }
  | { status: 'retrying'; attempt: number }
```

PARSER / COMPILER:
- Phase 1 — Lexer: Character-by-character tokenization. Return typed Token[] array.
- Phase 2 — Parser: Recursive descent. Return typed AST with discriminated union node types.
- Phase 3 — Evaluator/Transformer: Walk AST, apply transformations or evaluate expressions.
- Error recovery: Report position (line, column), continue parsing after error node.

ANIMATION ORCHESTRATION:
- Multi-element stagger: CSS `animation-delay: calc(var(--i) * 80ms)` on list items.
- Scroll-triggered: IntersectionObserver toggles `.is-visible` class → CSS transition plays.
- Exit animations: Clone element, animate out, then remove from DOM (or use View Transition API).
- Complex sequences: WAAPI (`element.animate([from, to], options)`) for JS-controlled timelines.

ALGORITHMS:
Always include at the function top:
```typescript
/**
 * [Algorithm Name]
 * Time:  O(n log n)
 * Space: O(n)
 * Approach: [brief description]
 * Example: input=[4,2,7,1] → output=[1,2,4,7]
 */
```
